Forms

Use data-b-form-ajax="true" to submit a form with fetch without leaving the page. Choose where to render the response and optionally ask for confirmation or remove the form.

AJAX submission#

Set data-b-form-ajax to exactly true to enable AJAX submission. Set data-b-form-ajax-target to a CSS selector for the element that receives the response. 

<form action="../api/contact.json"
      method="get"
      data-b-form-ajax="true"
      data-b-form-ajax-target="#contact-result">
    <input class="form-input" type="text" name="name" />
    <button class="button button-primary" type="submit">Send</button>
</form>

<div id="contact-result" data-b-use-template="#contact-template"></div>

BitsyJS cancels native submission before looking for the target. If the selector is missing or matches nothing, BitsyJS logs a warning and sends no request.

Methods, URL and body#

The method comes from the form's method attribute and is limited to get, post, put, patch and delete. Anything else, including an empty attribute, falls back to get. 

<!-- GET: fields are appended to the action URL as a query string -->
<form action="/search" method="get" data-b-form-ajax="true" data-b-form-ajax-target="#results">

<!-- POST: fields are sent as the request body -->
<form action="/users" method="post" data-b-form-ajax="true" data-b-form-ajax-target="#result">

Fields are collected with new FormData(form), then converted to URLSearchParams. For get the parameters are appended to the action URL, keeping any query string the action already has; for every other method the same URLSearchParams object becomes the body. When the form has no action, the current page URL is used as the base.

Rendering the response#

Forms use the same parser and renderer as remote data. JSON is parsed, HTML and other text/* responses are read as strings, and images become a Blob. Other responses are parsed as JSON if possible or kept as text. Without a template, BitsyJS writes to the target's innerHTML, serializing objects as indented JSON first. Use only trusted responses. 

<template id="contact-template" data-b-remote-data="response">
    <p>Status: {response.status}</p>
    <p>{response.message}</p>
</template>

Use data-b-use-template on the target to select a template. The template's data-b-remote-data value names the response in its scope. Each submission re-parses the original template, so placeholders resolve against the latest response. For lists, bind to the b-for loop alias to render each response's items.

Loading state, confirm and removal#

While the request runs, BitsyJS adds is--loading to the form and its submit controls, disables enabled submit controls, and ignores additional submissions for that form. It restores only the controls it disabled when the request finishes. Set data-b-form-indicator to use a different loading class. 

<form action="/users"
      method="post"
      data-b-form-ajax="true"
      data-b-form-ajax-target="#user-list"
      data-b-form-indicator="is--loading"
      data-b-form-confirm="Create this user?"
      data-b-form-remove-on-submit="true">

data-b-form-confirm passes its message to window.confirm. If the user cancels, BitsyJS sends no request. data-b-form-remove-on-submit="true" removes the form after BitsyJS parses and renders a successful response. A non-2xx response logs an error, leaves the target unchanged, and keeps the form on the page.

Validation runs first#

If the form also has data-b-validate-form="true", BitsyJS validates the fields first. An invalid form displays errors and sends no request. A valid form proceeds to AJAX submission. 

<form action="/users"
      method="post"
      data-b-validate-form="true"
      data-b-form-ajax="true"
      data-b-form-ajax-target="#result">
    <div class="form-field">
        <label class="form-label" for="email">Email</label>
        <input class="form-input" id="email" name="email" data-b-validate="required|email" />
        <small class="form-text" data-b-validate-message="email"></small>
    </div>
</form>

The rules, the message slots and the class names are described on Validation.

Native forms still work#

BitsyJS attaches a submit listener only when data-b-form-ajax or data-b-validate-form is set to true. With validation alone, an invalid form stays on the page and a valid form submits natively.

You can add AJAX submission and response rendering to a native form without changing its fields.

What it does not do#

  • No file uploads. The body is URLSearchParams built from FormData, so a File value is converted to a string instead of being sent as a part.
  • No error UI. If the request rejects, returns a non-2xx status, or response processing throws, BitsyJS logs the error and removes the loading indicator.
  • No redirection, history or focus handling after the response. Whatever the template renders is the whole feedback.
  • Listeners are attached once during run(). A form inserted into the page later is not wired, and the data-b-form-* attributes stay in the DOM.
